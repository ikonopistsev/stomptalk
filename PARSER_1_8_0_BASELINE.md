# Исходный замер stomptalk 1.8.0

Дата: 27 октября 2026 года. Замер сделан до изменения реализации парсера.

Использован существующий `test/purestomp.c`. Добавленный рядом проект `../purestomp/main.c` содержит побайтно такой же исходник. Тест выполняет **10 млн итераций по 10 кадров: 100 млн кадров за прогон**. Размер повторяемого входа — 838 байтов, всего 8,38 ГБ входных данных за прогон. Вход содержит LF, CRLF, escaping и тела с `content-length` и без него. В каждой итерации весь вход передаётся одним вызовом; разрывы входа этим замером не покрываются.

## Условия

- Исходники: commit `54a926c34c4fa6274357d2683920125a5bbfb1b3`; `src/`, `include/` и `test/` совпадают с HEAD.
- CPU: Intel Core i7-12700K. Процесс закреплён за логическим CPU 2, его SMT-сосед — CPU 3.
- ОС: Linux 7.2.10-gentoo-dist, x86-64, glibc 2.43.
- Компилятор: GCC/G++ Gentoo 15.3.0 p8.
- Сборка: C99 / C++14, `-O3 -DNDEBUG -march=x86-64 -mtune=generic`, без LTO. Тест компилируется C-компилятором и линкуется с реализацией C++.
- Один полный прогрев, затем три измерения подряд. Время — монотонное wall-clock время запуска процесса, включая его небольшой стартовый расход.
- Governor: `powersave`; частота и фоновая нагрузка не фиксировались. Системные настройки не менялись.

Текущий `CMakeLists.txt` уже имел пользовательские изменения. Для воспроизводимого исходного замера использованы явные команды сборки ниже, без изменения CMake и без его дополнительных настроек тестовых целей.

Все четыре запуска завершились с кодом 0 и одинаковым результатом:

```text

connected 10000000, frame 100000000, json 10000000, total 670000000
```

Это исходный результат парсера с существующими C callbacks. Он не измеряет сетевой RPC, выделение прикладных сообщений или сборку тела клиентом. Встроенный старый комментарий о 8,351 с относится к другому замеру версии 1.7.0 и не используется как сравнимая база.

## Воспроизведение

После начала v2 приведённые ниже команды относятся к исходному checkout 1.8.0. Для purestomp доступны также [неизменённые src/include/test](artifacts/parser-v2-implementation/stage-1/legacy/); запуск этих исторических команд на текущих src/include v2 не воспроизводит 1.8.0.

Команды из каталога `stomptalk/`:

```sh
mkdir -p /tmp/stomptalk-baseline-20261027
gcc -std=c99 -O3 -DNDEBUG -march=x86-64 -mtune=generic \
    -DSTOMPTALK_STATIC -DSTOMPTALK_VERSION=1.8.0 -Iinclude \
    -c test/purestomp.c -o /tmp/stomptalk-baseline-20261027/purestomp.o
g++ -std=c++14 -O3 -DNDEBUG -march=x86-64 -mtune=generic \
    -DSTOMPTALK_STATIC -DSTOMPTALK_VERSION=1.8.0 -Iinclude \
    src/parser.cpp src/stomptalk.cpp \
    /tmp/stomptalk-baseline-20261027/purestomp.o \
    -o /tmp/stomptalk-baseline-20261027/purestomp
time taskset -c 2 /tmp/stomptalk-baseline-20261027/purestomp
```

Последнюю команду выполнить один раз для прогрева и ещё три раза для измерения. При новом сравнении сохранить исходный бинарный файл 1.8.0 и чередовать старую и новую версии; CPU 2 должен быть доступен на проверяемой машине. Для другой архитектуры заменить целевые флаги и заново измерить обе версии.

## Проверки перед модернизацией

Существующие **16 unit-тестов прошли**. Они отдельно собраны с `-O2 -UNDEBUG`: в тестах используется `assert`, поэтому обычный Release с `-DNDEBUG` недостаточен для проверки корректности.

```sh
g++ -std=c++14 -O2 -UNDEBUG -march=x86-64 -mtune=generic \
    -DSTOMPTALK_STATIC -DSTOMPTALK_VERSION=1.8.0 -Iinclude \
    src/parser.cpp test/unit_test.cpp \
    -o /tmp/stomptalk-baseline-20261027/unit_test
/tmp/stomptalk-baseline-20261027/unit_test
```

Отдельная проверка генерации кода для `SEND` (4 байта), `SUBSCRIBE` (9) и `content-length` (14) показала: GCC 15.3.0 и Clang 23.1.4 при `-O3 -march=x86-64` встроили и `memcmp` с константной длиной, и сравнения через безопасные загрузки. В этих пробах нет инструкций вызова сравнения или копирования. Определение маленького помощника ниже места вызова также не помешало встраиванию. Это проверка машинного кода, не замер ускорения парсера.

Сырые результаты также сохранены в проекте: [results.json](artifacts/parser-v2-review/2026-10-27/evidence/purestomp-results.json), [команды сборки](artifacts/parser-v2-review/2026-10-27/evidence/purestomp-build-commands.txt), [лог unit-тестов](artifacts/parser-v2-review/2026-10-27/evidence/original-unit-tests.log), [проба сравнений](artifacts/parser-v2-review/2026-10-27/evidence/compare-probe.cpp).
