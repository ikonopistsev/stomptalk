# Проверка реализации Codex — 28.10.2026

Объект: рабочая ветка `stomptal-smid-2`. Это самостоятельная проверка автора
изменений, не независимое заключение Claude. Внешняя попытка закончилась
`API Error ... EAI_AGAIN`, без ответа модели и без отказов инструментов.

## Соответствие договорённостям

- Сканер — обычный static inline метод; уровень выбирается при инстанцировании
  состояния parser. Верхняя реализация передаёт остаток следующей: 32/16/8/byte.
  `key=true/false` — константа в месте вызова. Нет indirect call/CPUID на header.
- equal<N> раскрывается шаблоном; runtime equal обходит полные SIMD-блоки.
  **Их программный путь — memcmp, а не собственный SWAR equal**. SWAR здесь
  относится к поиску разделителей через uint64. Это уточнение пользователя
  учтено в README и ТЗ; прежнее описание общей цепочки для equal было неточным.
- Общие SIMD load/mask используются для сравнения и поиска. SWAR zero_mask
  намеренно не применяется к all-equal: borrow-контрпример сохранён в артефактах.
  Искусственная унификация этих редукций не вводится.
- Обычный content-length и packed SIMD-константа разделены. Generic equal
  никогда не ожидает packed-строку. SIMD content-length читает 8 байт с начала
  и 8 с конца 14-байтного диапазона, даже у границы защищённой страницы.
- Дерево состояний, стек, antoull, escaping и публикация payload не изменены.
  Изменились три обращения к backend в parser_states.hpp. Runtime-проверки
  клиентского C API сохранены; внутренние предусловия проверяются assert.
- parser_avx2.cpp не лишний: это target-контекст общего дерева состояний,
  разрешающий inline AVX2 без повышения ISA базового объекта. При выключении
  AVX2 объект исключается из CMake. Runtime CPU/OS gate остаётся при init.

## Замечания и пределы вывода

P1 / скорость: предварительная O2-серия не доказала общее ускорение. Есть
замедления; отдельный GCC SWAR sample шумный (spread ~53%). Итоговая серия
содержит все samples, Os/O2/O3, оба компилятора, три backend и отдельные сценарии.
Менять принятую серверную ветку только на основании новой структуры нельзя.
Итоговые значения и top-5 будут в README.md этого каталога.

P2 / простота: активных src/include стало 23 вместо 25. Строк 2726 вместо 2719,
байт 84621 вместо 86386 (без старых `_` helpers, с generated dictionaries).
То есть количество прослоек уменьшилось, но существенного сокращения объёма
кода нет. Удаление исторических файлов не следует выдавать за упрощение
действующего алгоритма.

P2 / API: overload is_header с char-array предназначен для строковых литералов:
последний завершающий NUL исключается из длины. Для произвольного массива с
точной длиной нужен stomptalk_view. Внутренний helper не входит в C ABI.

P2 / настройки: выключение SSE2 выключает также AVX2 — верхняя реализация
использует SSE2-tail. AUTO теперь возвращается к SWAR, а не scalar. Это явное
изменение выбора backend, проверенное тестом. Принудительный запрос отсутствующей
реализации остаётся ERROR_BACKEND. CPU features и compiled mask не смешиваются.

## Проверки

GCC/Clang: SSE2-only и SWAR-only; прямые DISABLE-макросы; раздельное отключение
AVX2 parser/classifier; debug; shared/exported C symbols; installed C99 client;
ASan/UBSan; generator reproducibility. Все прошли.

Guard pages с двух сторон, длины 0..65/97/128/257 у equal, смещения 0..31,
каждый несовпадающий байт и high-bit; у сканера длины 0..129, все позиции событий,
все 256 значений и соседние borrow-байты. Существующие parser tests проверяют
fragmentation, limits, escaping, binary payload и завершение фрейма.
Fuzz — 405222 запусков за 31 секунду, ASan/UBSan без находок; LSan отключён.
Это ограниченный ручной прогон, не доказательство отсутствия ошибок.

## AVX-Memmove

Локальный reference: `snapshot/reference/avx-memmove/memcmp.c`,
`memcmp_large_eq_a`, строки 1143–1271. Использована идея выбора доступной ширины
и обработки остатка. Реализация не подключается и код не переносится дословно.
Типизированные невыровненные dereference из reference не заимствованы;
используются memcpy для uint64 и unaligned SIMD loads. Его большой каскад,
AVX-512, выравнивание входа и streaming stores не нужны для этого этапа.
