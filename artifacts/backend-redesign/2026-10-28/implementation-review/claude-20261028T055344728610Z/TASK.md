Пользователь просил:
- простую общую организацию scanner/equal вместо множества переходников;
- верхний скомпилированный backend задаёт доступные нижние уровни;
- scanner НЕ шаблонный: AVX2 32 → SSE2 16 → SWAR 8 → bytes;
- equal<N> раскрывает известный размер шаблоном; runtime-length перегрузка;
- is_header как функтор с шаблонным оператором и runtime views;
- отдельные ordinary/packed SIMD content-length константы, безопасный хвост;
- отключаемый AVX2 либо оба SIMD, CPU/OS gate при init, хорошее inlining;
- сохранить хвостовые переходы, stackbuf, antoull, escaping, C ABI;
- удалять лишние файлы. parser_avx2.cpp оставлен как AVX2 target-контекст
  общего дерева состояний, не отдельный алгоритм.

Важное уточнение: в реализации equal для остатка <16 используется один memcmp;
отдельного SWAR equal нет. SWAR относится к поиску разделителей через uint64.
Автор ранее неточно назвал этот каскад одинаковым для обоих действий; описание
исправлено. Оцени обоснованность этого разделения и самый простой полезный
вариант; не объявляй memcmp автоматически медленным или неинлайнящимся.
Старый borrow-based zero_mask не точен по всем байтам — проверь, что он не
используется для all-equal. Контрпример в evidence/mask-counterexample.json.

Проверь C++14, границы/aliasing/alignment, обе длины и null/0, compile-time
каскад vs runtime CPU dispatch, target isolation, optional configurations,
возможные ODR/target-attribute проблемы, отсутствие лишних runtime вызовов.
Посмотри AVX-Memmove и укажи конкретные файлы/строки заимствуемой идеи.
Код не должен тащить эту библиотеку, требовать padding или возвращать C++ ABI.
