# Перенос данных при фрагментации purestomp — 29.10.2026

Проверен опубликованный fce7385 на том же наборе из 10 кадров / 838 байт.
Диагностическая копия собирается отдельно в build/source, рабочие src/include/test
не меняются. Счётчики добавлены непосредственно перед тремя операциями:
stackbuf::push(data,size) — memcpy, stackbuf::retain — memmove и перемещение
массива header-дескрипторов в recycle. Однобайтовая запись декодированного escape
через push(char) в счётчик memcpy не входит.

Счётчики сбрасываются после проверки содержимого, перед обычным циклом purestomp.
Поэтому reference-разбор и preflight не учитываются. Для каждого размера куска
сначала выполнен один повтор набора, затем три: все счётчики точно утроились.
Обе серии прошли проверки содержимого и итоговых результатов исходного purestomp.
Диагностическая сборка — Clang 23, O2, SSE2, без PGO; её скорость не измеряется.

Ненулевой сдвиг stackbuf выполнен на 436 из 838 размеров куска.
При размере 1 байт NUL-терминатор заканчивает отдельный execute: следующий
вызов сначала сбрасывает накопитель, затем начинает новый кадр. Копирование
метаданных при границах входа работает, но удаляемого префикса перед активным
кадром нет. На других размерах один вызов может закончить предыдущий кадр
и начать следующий; сохранённый остаток затем перемещается в начало накопителя.

При 512 байтах есть один сдвиг массива header-дескрипторов на 96 байт, но
stackbuf не сдвигается: перед данными активного кадра нет сохранённых строк
предыдущих кадров. При подаче всех 838 байт остаются memcpy для escaping,
но оба вида memmove отсутствуют. Payload в эти копирования не входит.

Полные результаты: counts-1.csv и counts-3.csv. В них calls считает все вызовы,
nonzero — вызовы с ненулевой длиной, bytes — суммарный объём. Например, на кусках
по 2–8 байт перемещение header-дескрипторов вызывается с нулевым размером;
это отдельно от ненулевого сдвига строк stackbuf.

Запуск: `python3 artifacts/buffer-moves/2026-10-29/run.py`.
Точные команды и hashes исходников — run.json; trace.c/trace.h и преобразования
в run.py полностью описывают диагностическую вставку. Результаты не заменяют
[замер скорости без счётчиков](../../purestomp-chunks/2026-10-28/README.md).
