# equal: пустой хвост и пустой view — 2026-10-28

База `5af4d3d11626e08d06775c0096d47b77fb90d9e9`.
Пользователь указал на `size == 0 || memcmp(...) == 0` внутри сравнения.
Предыдущий аудит обосновал обработку NULL/0, но оставил её на слишком низком
уровне. Здесь отделены контракт view и сравнение уже корректных диапазонов.

## Откуда приходит ноль

`sse2::equal<16>` сравнивает блок, затем вызывает `equal<0>(data+16, text+16)`.
AVX2 аналогично заканчивает точные кратные 32. Runtime-цикл также оставляет
остаток 0 при кратной длине. Это нормальное завершение сравнения, а не плохой
исход или обязательно пустое имя заголовка. Если предыдущие блоки совпали,
пустой остаток равен пустому остатку, поэтому результат true.

`memcmp` допускает размер 0 и возвращает 0; указатели всё равно должны быть
корректными. NULL не становится допустимым аргументом только из-за нулевой
длины: [C draft N1570, §7.24.1 p2 и §7.1.4 p1](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf).
То, что конкретная libc не падает на NULL/0, не устанавливает контракт C++14.

## Изменение

- В обоих scalar::equal оставлены assert(data && text) и прямой memcmp.
- is_header принимает nullable пустые views как прежде и обрабатывает их сам.
  Обычный непустой путь расположен первым. Для literal Size — compile-time
  величина; условие пустой константы не добавляет runtime-теста известным именам.
- SSE2/AVX2 заканчивают сравнение тем же каскадом; новых методов/специализаций нет.
- C API, его ошибки, parser state machine и существующие тестовые ожидания прежние.

## Повторная проверка оставшихся условий

| Место | Почему условие остаётся / что изменено |
| --- | --- |
| swar.hpp, два equal | Проверка нуля удалена. Работа с nullable view перенесена в адаптер. |
| sse2.hpp / avx2.hpp, equal | size >= 16/32 защищает реальный SIMD load; несовпадение блока завершает сравнение. Остаток 0 допустим. |
| sse2.hpp / avx2.hpp, equal<N> | Size < 16/32 и рекурсивная длина выбираются при компиляции. Базовый memcmp(...,0) сворачивается. |
| is_header.hpp | Сравнение длин нужно до чтения; пустой nullable view обрабатывается единственным слоем, которому он передаётся. |
| name_group.hpp | constexpr выбор позиций и sizeof-проверки не являются runtime-защитой; точное сравнение после выбора кандидата обязательно. |
| scanners | Нулевые masks перед ctz и доступный размер перед load зависят от входа. Удаление этих условий даёт UB/выход за диапазон. |
| parser::append(range) | Нулевой диапазон реально приходит на разделителе. Он не должен присваивать ненулевой data пустому token и запускать его перенос. Это не невозможный отказ. |
| parser::own | Пустое значение заголовка допустимо и имеет NULL/0. Пропуск нужен до копирования; перенос резервирования здесь не решает вопрос адреса. |
| antoull | Ноль цифр и переполнение — реальные ошибки wire input. Assert не заменяет эти проверки. |
| stomptalk.cpp | Проверены C entry points, layout и find_header. Nullable аргументы и заданные ошибки относятся к внешнему контракту. Внутреннее raw equal не обязано их повторять. |

## Проверки

GCC 16 / Clang 23 × Os/O2/O3: CTest/C99 прошли. Debug/assert и ASan/UBSan
с assertions также прошли. Существующий suite включает NULL/0 views, длины
0..65, 97/128/257, несовпадения, alignment и guard pages; 21008 streams /
4198701 checks. Новые тесты, повторяющие реализацию, не добавлялись.

Для всех шести сборок `.text` и `.rodata` одинакового parser+consumer probe
**побайтно совпадают** с базой. Полный parser использует сравнения известных
ненулевых имён, а runtime is_header — отдельный C++ helper. Эта правка разделяет
ответственность слоёв; ускорение полного парсера ей не приписывается.
Вывод не распространяется на произвольную программу, напрямую использующую
runtime equal: без проверки нуля такой helper может вызвать memcmp и для
нулевого остатка. Отдельный микробенч этого клиентского helper не проводился.

Контроль purestomp: CPU 4, SSE2, 10 млн кадров, прогрев + 3 чередующихся пары.
Clang в этом прогоне шумный: spread до 37.52%. Разницу timing для побайтно
одинакового кода не трактуем как эффект патча. Все samples в checks.json.
