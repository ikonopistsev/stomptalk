# Одна content-length константа — 28.10.2026

Удалено отдельное строковое представление имени в parser backend. Осталась
`alignas(16) constexpr char content_length_wire[] = "\ncontent-length:";`.
Прямой вход: прежнее сравнение 16 байт через выбранный backend. Собранное имя:
прежний memcmp 14 байт, но эталон теперь `content_length_wire + 1`. Смещение
не применяется к входному имени. Длина выводится как `sizeof(wire) - 3`
(LF, colon, завершающий NUL). Условия выбора пути и scanner не менялись.

Сравнение с **wire** из серии `../runs/20261028T062508203190Z`: прежняя
цепочка key/value, обе сборки static PIC. Эксперимент hdrline по-прежнему OFF.

## Машинный код

В шести сборках GCC 16 / Clang 23 × Os/O2/O3 размер .text не изменился.
Clang: .text совпадает байт в байт. GCC: после исключения RIP-relative
адресов констант инструкции полностью совпадают. Это проверено по всему
дизассемблированному executable, а не только по одной функции. GCC .rodata
уменьшилась на 20 байт в O2 и 32 байта в O3, в Os размер прежний. Выравнивание
16-байтной константы сохранено; 14-байтный memcmp не требует такого выравнивания.

## Контроль полного парсера, O2

P CPU 4, исходный purestomp corpus, 10 млн кадров на запуск, прогрев и пять
чередующихся повторов. Проверены все полезные счётчики и CPU affinity.
Медиана млн кадров/с; положительная дельта времени означает замедление.

У GCC/SWAR и GCC/AVX2 есть выбросы, все повторы сохранены. Ускорение не
заявляется: это устранение дублирования константы с прежним алгоритмом.

## Проверки

Все шесть Release-сборок прошли CTest/C99, 20688 streams / 5980812 checks
на all-backend сборку. Также проверены Clang/O2 с hdrline=ON, GCC без SSE2/AVX2
и Clang/ASan/UBSan с hdrline=ON. Guard pages проверяют обычное имя на 14 байт
и wire на 16 байт у обоих краёв; все misalignment/fragmentation тесты сохранены.
Новых тестов, повторяющих реализацию, не добавлялось. Генератор воспроизводим.
Отдельные perf profiles, GNU time и новый fuzz на этом шаге не запускались.
