# Сохранение SIMD-масок заголовков: изолированный эксперимент

Цель — проверить предложение сначала получить несколько границ, затем обработать
их существующим деревом парсера. Production `src/` и `include/` этим экспериментом
не меняются. Исходная точка — v2 после этапа 3 с восстановленным antoull.

## Варианты

| Вариант | Что сохраняет | Дополнительный объект cursor, байт |
| --- | --- | ---: |
| baseline | прежний поиск первого события | 0 |
| mask1 | одна маска для 16 байт, все её позиции используются | 32 |
| mask256 | до 16 масок / 256 байт входа | 88 |
| mask32k | до 2048 масок / 32 КиБ входа | 8216 |
| positions128 | до 128 смещений uint32, максимум 32 КиБ за заполнение | 536 |

Одинаковая ширина SSE2 исключает смешение эффекта алгоритма с переходом на AVX2.
Маски отмечают NUL, LF, CR, двоеточие и обратную косую черту. Существующее дерево
по-прежнему решает, допустим ли символ, выполняет escaping, разбирает content-length,
возвращает кадры и потоковые части payload. Скалярный/SWAR backend не заменён.
Многоблочный сканер останавливается на пустой строке; последняя допустимая загрузка
может захватить до 15 байт тела, но оно не размечается целиком. Остаток меньше 16
байт читается побайтово. Перед каждым execute указатели cursor сбрасываются.

Память cursor входит в размер parser, который учитывает C API memory requirements.
Для эксперимента она фиксирована; это не предложение нового публичного контракта.
Tailcalls и накопитель сохранены. Массив смещений ограничен; при переполнении
следующее заполнение продолжает с первого невыданного участка.

## Методика

GCC, CMake static PIC, Os/O2/O3, CPU 2. Сначала сборки, unit/C99-тесты,
прямая сверка scanner со scalar на 1 846 132 проверках в каждом варианте,
guard pages, Clang ASan/UBSan и короткий ручной fuzz. Затем последовательные
измерения без сборок/fuzz/известного активного Claude-запуска.

Purestomp: 10 млн кадров, прогрев + пять повторов с ротацией пяти вариантов.
Выбранный по O3 вариант дополнительно сравнивается с baseline на 100 млн кадров,
три чередующихся пары. Измеряется время дочернего процесса; это не новый GNU time
отчёт. Синтетические потоки проходят настоящий parser и consumer: аллокация и
загрузка файла вне таймера, 21 сценарий, прогрев + пять повторов. Число повторений
сценария одинаково для всех вариантов и выбирается по baseline около 100 мс.
Проверяются consumed, frames, headers, body bytes, CONNECTED и JSON counters.

Сценарии: 0/1/8/32/64 заголовка с LF и CRLF; 16 значений по 128/1024 байта;
escaping и literal CONNECTED; фрагменты 1/7/31/63 байта; известное тело 64 КиБ
с ложными разделителями; пакет с таким телом; 32 коротких кадра в одном буфере.
Отчётные значения синтетики — нс на полный кадр. Полный parser/consumer важнее
изолированной скорости извлечения битов. Набор искусственный и не заменяет
реальную смесь RPC. Счётчики полезной работы не заменяют unit/fuzz проверки полей.

Профили O3: perf record cycles:u, 997 Hz, затем perf stat cycles/instructions/
branches/branch-misses. Self-доли функций не доказывают причину через I-cache.
Данные одной машины нельзя переносить на другой CPU или AVX2 без измерений.

## Файлы и повторение

- `event_scan.hpp`, `check_cursor.cpp` — прототип и прямые проверки.
- `prepare.py` — создаёт отдельные source-копии и fixtures в чистом каталоге.
- `sources.json`, `cases.json` — SHA256 и ожидаемые счётчики.
- `run.py` — проверки и измерения; новый каталог `runs/<UTC>/` для каждого запуска.
- `summarize.py runs/<UTC>` — CSV времени, размера .text и пяти функций.
- [Изученные проекты](SOURCES.md).

Существующие `sources/` и `fixtures/` уже подготовлены: для повторения достаточно
`python3 artifacts/header-mask-study/run.py` из корня stomptalk. Не запускать
параллельно с другими benchmark. Старые неуспешные запуски сохранены: два
-Werror maybe-uninitialized при проверке cursor исправлены явной инициализацией
служебных полей; один подготовительный запуск прерван для исправления имени
счётчика body_bytes в harness. Их время не включается в результаты.

## Результат — 2026-10-27

Рекомендация: сохранить текущий потоковый сканер. В проверенной интеграции
карта не ускоряет общий parser, хотя одна маска иногда помогает отдельным
коротким сценариям. Полная двухэтапная переделка этим опытом не проверена.

Purestomp, 10 млн кадров, медиана пяти повторов (секунды):

| Os | 0.9431 | 1.0297 (+9.18%) | 1.0699 (+13.44%) | 1.0839 (+14.93%) | 1.1198 (+18.73%) |
| O2 | 0.6569 | 0.7382 (+12.38%) | 0.7880 (+19.96%) | 0.7927 (+20.68%) | 0.8250 (+25.59%) |

Карта добавляет хранение/чтение состояния и обработку всех событий. На длинных
значениях построение карты пустых блоков особенно невыгодно. Это объяснение
по структуре алгоритма; отдельная причинная проверка каждой инструкции не
выполнялась. Локальные выигрыши mask1 не перекрывают общий проигрыш. Оснований
заявлять улучшение кэша CPU нет.

Проверки: все 15 Release-сборок прошли CTest; 12 прямых cursor-прогонов прошли
по 1 846 132 проверки. Четыре ASan/UBSan-сборки, их CTest и cursor-прогоны
прошли. Fuzz: 225151 / 230608 / 190441 / 229465 запусков, по 11 секунд,
без находок. Это короткая ручная проверка, не исчерпывающий fuzz.
Счётчики всех benchmark и perf-прогонов совпали. SHA256 измеренных источников
проверены. Измерения завершились до чтения выводов внешнего Claude.
