# Разбор по файлам: гарантии между слоями

База — `e30e2aa8b2b49daebaf07ceea3dcbccdfe8177fe`, снимок в `before/`.
Исходный stackbuf 1.8.0 не изменяется: пользователь использует его только для
char и не копирует. Здесь пересматривается закрытая реализация v2 за C API.
Новых классов, allocator-ов, флагов состояния или принудительных inline нет.

## Единственная проверка места

`byte_left_ = byte_capacity - byte_begin_ - decoded_active_bytes`.
`byte_begin_` — физические байты уже готовых результатов. В активных байтах
учитываются и ссылки на вход: при возврате их ещё понадобится сохранить.

1. Начало кадра: `byte_begin_ = bytes_.size()`, `byte_left_ = bytes_.available()`.
2. Перед принятием положительного диапазона/decoded byte `reserve` сравнивает
   count с byte_left и вычитает count. Это единственная обычная проверка места.
3. При отказе `byte_left_ + byte_begin_` — доступное место всего активного кадра.
   Если count больше, возвращается BYTE_LIMIT с прежним точным offset. Иначе
   возвращается OUTPUT_FULL, после выдачи порции будет освобождён byte_begin.
4. `own`/`own_token` копируют только уже учтённые байты, по одному разу.
   Открытый token переносится после остальных метаданных, поэтому его продолжение
   пишет в конец. Следовательно, каждый физический push уже обеспечен местом.
5. Перед возвратом активные ссылки переводятся в накопитель. При recycle старый
   префикс удаляется, `byte_left_ += byte_begin_`; доступное физическое место
   снова равно byte_left. Это проверяется assert в Debug/sanitizer сборках.

Ни отказ, ни пустой append не изменяют счётчик. Payload в него не входит.
При завершении чистого borrowed кадра его строки не занимают накопитель;
следующий кадр снова начинает расчёт от фактически записанных байтов.

## Что именно проверяют тесты

Сохранены API BYTE_LIMIT/OUTPUT_FULL, их приоритет и точные offsets, включая
переполнение при наличии готовых результатов. Удалены только проверки отказа
внутреннего push, который теперь вообще не вызывается без места. Добавлено
retain всего заполненного префикса (остаток ноль). Некорректные длины не подаются
во внутренний content-length helper; вместо этого public parser проверяется
на `content-lengt` и `content-lengthx` с нечисловым значением как обычными заголовками.
Все варианты разрезов и chunk=1/7 сохраняются.

Форсированные classifier-ы проверяются непосредственно из теста, а не через
неиспользуемую production-возможность выбора. Публичный AUTO проверяется отдельно
на всём словаре и в сборках с отключёнными расширениями.

## Измеряемые варианты

- `closed-buffer`: изменение инвариантов и учёта места, helpers ещё в parser_impl.
- `visible-helpers`: те же короткие helpers видны обоим parser TU. Это обычные
  inline-члены класса; force-inline всего дерева не добавляется.

Упрощение исходника и ускорение оцениваются отдельно. Исходные замеры старого
stage-5-buffer здесь не переиспользуются как доказательство: в том опыте были
добавлены push_reserved/friend и сохранён прежний счётчик/старое дерево; тот
вариант регрессировал и был отклонён. Новые результаты хранятся в runs/.
