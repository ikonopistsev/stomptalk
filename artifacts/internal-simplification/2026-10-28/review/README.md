# Claude: ревью упрощений и поиск дальнейших оптимизаций

Предмет: `5af4d3d11626e08d06775c0096d47b77fb90d9e9` относительно
`e30e2aa8b2b49daebaf07ceea3dcbccdfe8177fe`. Исходники и evidence заморожены
в snapshot/; inputs.json содержит SHA-256 каждого файла.

Задание: [TASK.md](TASK.md). Проверить корректность снятых проверок и связей
reserve/stackbuf/own/publish/recycle, оценить простоту и ускорение отдельно,
найти максимум три следующие локальные оптимизации с планом проверки.
Отдельно исследовать headerless/fragmentation регрессии, O2 PGO escaping и
изменение машинного кода/инлайнинга. К материалам приложены существующие asm,
perf и сырые samples; авторские объяснения предлагается читать после кода.

Запуск этого исторического снимка из корня ветки:

```sh
python3 artifacts/internal-simplification/2026-10-28/review/run_claude.py
```

Общий `run-claude-smid-2-simplification-review.sh` теперь запускает
[актуальный пакет с уточнением equal](../../../equality-contract/2026-10-28/review/README.md).

По умолчанию используется `~/.local/bin/claude`, текущие модель/авторизация CLI,
таймаут 1200 секунд. При другом расположении передать `--claude /path/to/claude`.
`--check` только проверяет снимок и не вызывает API.

Claude получает Read/Glob/Grep и не меняет код, не запускает сборки/замеры.
Существующие результаты рассматриваются как evidence, новые ускорения — как
гипотезы до отдельного A/B. Runner не отключает permission checks.

Каждый запуск создаёт отдельный `claude-<UTC>/`:

- `TASK.md` — точный отправленный запрос;
- `stdout.jsonl` — поток ответов и tool calls;
- `stderr.log` — диагностика;
- `run.json` — команда, SHA, статус и проверка неизменности входов;
- `review.md` — итоговый ответ, только если Claude успешно его вернул.

Неуспешный запуск не выдаётся за проведённое ревью. Повторный запуск сохраняет
предыдущие логи и создаёт новую директорию. Экспериментальные исправления в
основной parser этим сценарием не вносятся.
