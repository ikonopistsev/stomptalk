# Этап 2 — сравнение имён, backend и разбор content-length

Ветка `stomptalk-smid`, 27 октября 2026. Это сравнение с предыдущей реализацией v2,
сохранённой в [before](before/), а не новый замер 1.8.0. Исторический baseline
1.8.0 и его сравнение с первой v2 остаются в [этапе 1](../stage-1/README.md).

## Код и границы изменений

- `src/is_header.hpp`: `is_header<Backend>(name, expected)` принимает два
  `stomptalk_view`, проверяет длины и сравнивает байты. Пустые views равны;
  ненулевой размер с null отвергается. SWAR — переносимый `memcmp`, SSE2 —
  блоки 16 байт, AVX2 — блоки 32 байта с безопасным коротким хвостом.
- `src/content_length.hpp`: отдельная проверка ровно 14 байт. Генератор готовит
  `alignas(16)` константу «первые 8 + последние 8». Вход загружается со смещений
  0 и 6, его выравнивание не требуется. SSE2 сравнивает один XMM-регистр;
  AVX2 для этого короткого имени использует VEX/XMM. Никаких 16/32-байтных
  чтений из 14-байтного входа нет. SWAR сравнивает две восьмёрки.
- Общий двухаргументный помощник и проверка content-length используют три
  backend через шаблонный параметр: runtime switch/CPUID на каждом сравнении нет.
  AVX2 код и его includes должны находиться в собственном target-контексте;
  вход в него разрешён после проверки CPU/OS. Это внутренние C++ помощники,
  внешний C ABI не изменён.
- `src/name_group.hpp`: длина выбирает группу; для групп от трёх имён
  constexpr-поиск выбирает различающий символ или пару символов. Полное
  сравнение обязательно. Пары имён проверяются напрямую. При отсутствии
  уникального селектора предусмотрен точный линейный fallback.
- Ядро включает только `methods.hpp` и `content_length.hpp`. Полный словарь
  `headers.hpp` используется отдельным клиентским `stomptalk_detect_header`.
  Его CPU-dispatch вынесен в `names.cpp`/`names_avx2.cpp`; AVX2 не требует
  глобального `-mavx2`. Методы парсер распознаёт через SWAR/constant memcmp.
- Семь неиспользуемых заголовков 1.8.0 в include переименованы с `_`:
  parser_hook, hook_base, antoull.h/.hpp, fnv1a, hashval, perf.
  [Проверка зависимостей и хеши](legacy-files.json). В src архивировать
  дополнительные файлы не понадобилось; `is_header.hpp` — новый помощник.

AVX2 здесь относится к **сравнению имён**. AVX2-сканера полного парсера пока нет:
доступны Scalar/SWAR/SSE2, и AUTO выбирает SSE2 на этой машине. Тело с длиной
пропускается по счётчику, без длины использует `memchr`; эта логика не менялась.
Текущие известные имена не длиннее 25 байт, поэтому широкая AVX2-ветка нужна
для общего сравнения, но не ускоряет текущий словарь сама по себе.

## Проверки

GCC O0/Os/O2/O3, Clang O3, ASan/UBSan: **8292 потоковых варианта,
1 674 956 проверок** на сборку. Проверены все 48 header ID, три backend,
длины 0..65 и 97/128/257, изменения каждого байта, high-bit различия,
смещения 0..31 и обе стороны защищённых страниц. Прямые проверки
content-length не зависят от общего классификатора.

[Полные логи](validation-aligned-final/checks.json), CMake shared/install и
отдельный C99-клиент прошли. [Сборка без AVX2 и финальный fuzz](post-aligned/checks.json):
seed 1805, 396559 запусков / 21 с, ASan/UBSan, без находок. Запуск ручной;
расписания нет. Предыдущий прогон с seed 1804 относится к предыдущему коду.
[Генератор воспроизводит все пять файлов](generator-aligned-check.json).

В [SSE2 листинге](header_compare_probe.s) видны `movq`, `movhps 6(...)`,
`pcmpeqb .LC0`, `pmovmskb`; в [AVX2 листинге](header_compare_probe_avx2.s) —
VEX-эквиваленты. `.LC0` имеет `.align 16`. Специализированные помощники
заинлайнены, вызовов других функций нет. Само наличие alignas не доказывает
ускорения: компилятор мог подготовить аналогичную константу и раньше.

## Оценка решения

Упрощение: ядро видит только необходимое имя; универсальное сравнение отдельно
от классификации и от специальной константы. Общие шаблонные группы заменили
ручные цепочки. Цена — три backend и отдельный target-контекст AVX2; они
проверены независимо, но не все ускоряют текущий словарь.

Ускорение: прирост всего Release/AUTO не доказан. Выигрыш есть на отдельных
группах/сценариях и Os/SSE2, регрессии оставлены видимыми. AVX2-сканер тела,
новые memory-функции, интеграция RPC и изменение накопителя здесь не добавлялись.
Замечания прошлого ревью о полном восстановлении форматирования ядра,
TCO в O1/Og и формальном C++14 lifetime результатов остаются отдельными;
этот отчёт не объявляет их исправленными.

Снимок итоговых исходников и SHA256 сохранены в perf-final. Для проверки:
`python3 artifacts/parser-v2-implementation/validate.py /tmp/stomptalk-validation`.
Замеры воспроизводятся measure.py с новым выходным каталогом; report.py
проверяет завершение, коды возврата, counters и соответствие исходников снимку.
