# Журнал изменений и измерений

## Этап 0 — исходная 1.8.0, 2026-10-27

Изменение: только ТЗ, ревью и отдельные тестовые артефакты. `src/`, `include/`, существующие `test/` и `fuzz/` не менялись. Commit исходной реализации: `54a926c34c4fa6274357d2683920125a5bbfb1b3`.

Проверки: старые 16 unit-тестов прошли с assert; новые 1 045 проверок 33 сценариев не дали неожиданных расхождений. Четыре известных ошибки и один вопрос совместимости явно выделены. Код ошибки проверяется даже при полном consumed. Результаты с дублями заголовков сравниваются как упорядоченные пары.

Скорость: purestomp — 8,146 млн кадров/с, медиана 12,275854 с на 100 млн кадров. Дополнительно сняты 11 сценариев, отдельный прогрев и три измерения каждого. Сравнения с предыдущим этапом ещё нет. Цифры в [baseline](baseline/README.md), все повторы и команды сохранены.

Ручной fuzz: три цели ASan/UBSan, лимит 15 секунд на цель, фактически по 16 секунд по журналу libFuzzer. 3 751 059 исполнений, exit=0, находок нет. Расписание отсутствует. Этот короткий прогон не является заключением о полной безопасности или семантической корректности.

Профиль: новый CPU-профиль не снимался. Использованы существующие RPC-отчёты для выбора следующих сценариев; ускорение FNV отдельно пока не доказано. Кодегенерация коротких сравнений и хвостовых переходов проверена по сохранённым листингам.

Решение: сохранить исходную базу, обсудить шесть вопросов контракта, затем начать scalar. Не добавлять пока AVX2, собственные memory-функции и индекс заголовков. Внешнее ревью Claude осталось неполученным из-за DNS; это ограничение, а не согласование проекта.

## Формат записи следующего этапа

- Название этапа, цель, commit/dirty diff и конкретное изменение.
- Оценка упрощения: какие состояния, специальные случаи, операции и правила владения убраны или добавлены; влияние на сложность клиента и тестирования.
- Оценка ускорения: механизм, сценарии, подтверждённые измерения либо гипотеза с минимальным экспериментом. Оба критерия обязательны на каждом ревью; существенная альтернатива текущему подходу выносится на обсуждение.
- Хеш сценариев и адаптера, компилятор/флаги/ISA/backend, CPU/affinity, ёмкости памяти, seed, разбиение входа, прогрев и повторы.
- Результат каждого unit-сценария; намеренное изменение ожидания и его причина. Известные ошибки 1.8.0 не маскируют новые ошибки.
- Сырые времена, медиана и разброс каждого perf-сценария, результат полезной работы. Процент изменения к **этапу 0** и **предыдущему этапу**.
- Найденная просадка: конкретные сценарии и изменённый путь; отдельный профиль со строками/инструкциями, если функции встроены. Не объяснять причину одним совпадением по времени.
- Размер машинного кода, объём копирования в отдельном измерении, аппаратные счётчики по доступности. Отсутствующее измерение отмечать явно.
- Матрица backend × `-Os`/`-O2`/`-O3`, полный профиль и топ до пяти значимых функций каждой ячейки. Для ускоренного backend отдельно показать вклад в скорость полного парсера относительно того же v2 без него; выигрыш микротеста не является приёмкой.
- Параметры и результат ручного fuzz, сохранённые и минимизированные находки, новые unit-случаи.
- Решение: принять, изменить или отложить; что осталось непроверенным.

Для сравнения новой и старой версии запускать их попеременно на одной машине. Не применять универсальный процентный порог, пока не понятен шум конкретного сценария. Малое изменение в пределах шума не объявлять ускорением; локальную регрессию не прятать за общей средней.

## Этап 1 — первая реализация v2, ветка stomptalk-smid

Рабочий C API и дерево состояний перенесены с выбранного backup на единый блок памяти владельца. Удалены callbacks и FNV из пути разбора; добавлены ordered frame/header views, потоковый payload без сохранения, обязательный терминатор, стабильные ID и exact name helpers. Исправлены подтверждённые проблемы 1.8.0/backup с нулевой длиной, первым NUL тела, leading escape ключа, неполным копированием SIMD-префикса и ошибкой терминатора. Header defaults настраиваются при init; failed push сохраняет исходный контракт сброса курсора.

Оценка упрощения: один C-контракт и одна рабочая область, полные метаданные на продолжениях, отсутствие callback/FNV-подсистем. Дополнительная цена — описатели результатов, резервирование логических строк и carry. Существующие хвостовые переходы сохранены; в debug/sanitizers используется тот же автомат через внешний run. Последующее упрощение убрало повторные обходы уже сохранённых полей без новых состояний.

Оценка ускорения: обычный CMake Release/AUTO — 6.580876 с против 12.408370 с на 100 млн кадров, 1.886×, полезные счётчики равны. Отдельно сохранена одинаковая матрица явных флагов Os/O2/O3 и три backend. Первоначальный SWAR проиграл scalar на O2/O3; переход к точному первому биту на little-endian дал 19–25% относительно прежнего SWAR и сделал его быстрее scalar. AUTO выбирает SSE2, иначе scalar. AVX2 не добавлялся.

Регрессии сохранены явно: в финальных O3-парах byte input примерно в 1,68 раза медленнее 1.8.0, chunk:7 — в 1,29 раза, escape-насыщенный короткий кадр — в 1,35 раза. Пустой SEND приблизился к исходной задержке. Для этих случаев сняты отдельные старые/новые профили. Накопитель отдельно измерен на байте, диапазоне и фрагментах: runtime-диапазон без просадки, фиксированные 7-байтные фрагменты O3 медленнее. Зависимость constant memcpy от контекста инлайнинга проверена дополнительным контролем; результат одного микротеста не подменяет полную приёмку.

Проверки финального кода: 8292 потоковых варианта / 737857 проверок на сборку; GCC O0/Os/O2/O3, Clang O3, ASan/UBSan, guard pages, отравление входа, CMake static/shared, установка и C99 клиент. Финальный ручной fuzz seed 1803: 80580 запусков / 31 с без находок. По всем промежуточным состояниям кода 356513 fuzz-запусков; это не один финальный прогон. Расписания нет.

[Отчёт, профили, топ функций, CSV, снимки и команды](../../../artifacts/parser-v2-implementation/stage-1/README.md). Инструментированные копии отдельно подсчитали строковые записи и carry, без использования их времён в benchmark. RPC/SWIG интеграция, другие архитектуры и дальнейшие оптимизации пока не включены. Решение: первая реализация готова к следующему циклу; полного отсутствия регрессий не заявляем.

## Ревью этапа 1 — раунд 3

По запросу пользователя код и результаты заморожены в [отдельном снимке](review-round-3/README.md): 3602 файла с SHA256. Независимый Codex с новым контекстом завершил ревью; Claude CLI записал JSONL, но завершился DNS EAI_AGAIN, ответа модели нет. Подготовлен runner для внешнего запуска, без изменения production-кода.

Codex сам собрал Release/CTest и проверил 19440 дополнительных streaming-комбинаций, включая 42792 OUTPUT_FULL и отравление входов. ASan/UBSan прошли с отключённым LSan из-за ограничения среды. Воспроизведён SIGSEGV GCC O1/Og на 1 MiB CRLF-heartbeat; O1 с существующим trampoline и проверенные O2/O3/Os проходят. Root повторил сохранённые O1/Og/O1-trampoline/O3 бинарники и подтвердил результат. Полные perf/fuzz заново не запускались.

Пользователь указал на нарушение исходной стилистики и уточнил, где SIMD для тела. Оба вопроса вошли в задание и независимый отчёт. Стиль действительно изменён сверх необходимых изменений алгоритма. Собственные SWAR/SSE2 ускоряют сканирование заголовков; тело известной длины пропускается по счётчику, без длины использует общий memchr, AVX2 пока отсутствует. Backend-матрица измеряет весь парсер с разными сканерами заголовков. Ускорение поиска NUL не доказано.

Оба критерия рассмотрены: форматирование не даёт машинного ускорения; текущие SWAR/SSE2 полезны на whole purestomp, но escaped/fragmented просадки сохраняются. До фиксации первой реализации остаются стиль, ясный TCO build contract и несколько пробелов тестов/документации. [Отчёт Codex](review-round-3/codex-independent-review.md), [проверка замечаний](review-round-3/root-triage.md). Снимок и производственные файлы повторно сверены по hash, изменения не вносились.

## Этап 2 — отдельные backend сравнения имён и content-length

По уточнениям пользователя добавлены отдельные SWAR/SSE2/AVX2 headers, шаблонные группы по длине и различающим символам, универсальный `is_header<Backend>(name, expected)` с двумя `stomptalk_view` и отдельный `is_content_length<Backend>`. Для последнего генератор заранее упаковывает первые/последние восемь байт в `alignas(16)` константу. Вход читается ровно в пределах 14 байт; SSE2 и AVX2/XMM машинный код сохранён. Общий классификатор заголовков ядром не вызывается и после разделения translation units не подтягивается статической линковкой purestomp. AVX2-сканер парсера не добавлялся.

Семь неиспользуемых headers 1.8.0 в include переименованы с `_`, их внутренние старые includes исправлены. Дополнительных неиспользуемых src-файлов не найдено. Новые именные помощники написаны с отдельной строкой открывающей скобки и FORCE_INLINE; полное восстановление форматирования старого ядра этим этапом не объявляется.

Проверки финального кода: 8292 потоковых варианта / 1674956 проверок в GCC O0/Os/O2/O3, Clang O3 и ASan/UBSan. Все 48 header ID, runtime/constant сравнения, три backend, изменения каждого байта, невыровненный вход и guard pages. Shared/install/C99 и сборка без AVX2 прошли. Ручной fuzz seed 1805: 396559 запусков / 21 с без находок. Снимок исходников, хеши и воспроизводимость генератора проверены.

Оценка упрощения: ядро включает только methods и content-length; общая проверка двух views отделена от классификации. Цена — три backend и собственный AVX2 target-контекст. FNV/memeq в действующих src отсутствуют; portable comparison использует memcmp. Для короткого content-length AVX2 намеренно использует XMM, широкая ветка применяется к общим сравнениям от 32 байт.

Оценка ускорения: Release/AUTO, 100 млн кадров — 6.875921 → 6.926181 с, +0.73% времени при разбросе 1.98%/4.12%; общего ускорения этапа не подтверждаем. Os/SSE2 быстрее на 5.51%, Os/SWAR медленнее на 4.02%. В O3 сценариях content-length/CRLF время снизилось на 3.80%/5.70%, byte/chunk:7 выросло на 1.28%/1.64%. Optional header lookup ускорился на плотной семибайтовой группе, но общий O2/O3 lookup регрессирует. Ни одна из этих просадок не скрыта общей средней.

Сняты девять новых профилей Os/O2/O3 × Scalar/SWAR/SSE2 и perf stat, топ до пяти функций с self >=1%, без потерь samples. [Полный отчёт этапа 2](../../parser-v2-implementation/stage-2-names/README.md) содержит CSV, команды, все повторы, снимки и ограничения. Решение: структурное разделение и корректность реализованы; общий прирост скорости не заявляется. Прежние замечания TCO O1/Og, формальный lifetime C++14 и оставшееся форматирование ядра остаются отдельными задачами.

## Этап 3 — antoull и внутренние предусловия

По запросу пользователя восстановлено шаблонное ядро antoull 1.8.0 для 1..18 цифр.
Checked overload сохраняет диапазон uint64 v2, leading zeroes, ошибки цифр и overflow.
Проверки допустимости views в приватных comparisons/classifiers заменены на assert;
публичная C-граница и реальные протокольные/ресурсные проверки сохранены.
[Подробный аудит](../../parser-v2-implementation/stage-3-antoull/assert-audit.md).

Оценка упрощения: знакомый развёрнутый конвертер вместо нового цикла, меньше дублирования
null-проверок; добавлены только необходимые правила 19/20 цифр ради прежнего контракта v2.
Накопитель, tailcalls, body и lifetime результатов не менялись. C++ конкатенация списков
и отдельный функтор проверены изолированным примером GCC/Clang C++14; production API
для этого не добавлялся. В Clang alignas повторяется на определении static member.

Оценка ускорения: три снимка before / только antoull / antoull+assert, одинаковые flags.
Release/AUTO, 100 млн кадров: **6.696866 → 6.940368 → 6.866015 с**. Вклад возврата
+3.64%, следующего изменения −1.07%, вместе **+2.53% времени**. Общая скоростная
приёмка не пройдена. Os/SWAR −6.57%, O3/Scalar +4.50%, O3/SWAR +2.39%, O3/SSE2 +2.20%.
O2/SSE2 медиана −3.05% при разбросе 5.93%, уверенный выигрыш не заявляется.

SEND с content-length: 31.49 → 35.93 нс, +14.09%; просадка уже в antoull-only.
Для него сняты три дополнительных profiles и perf annotate finish_value, без потерь
samples. Собственная доля finish_value: 5.42% → 10.50% → 12.16%.
Отдельный числовой микротест O3 с константной длиной 6 цифр: 12.64 → 2.35 нс;
18 цифр: 37.93 → 6.06 нс; одна цифра регрессирует. Улучшение конвертера не переносится
автоматически на весь парсер. `.text` O3 вырос 28639 → 35174 байт; причинная связь
с I-cache не установлена. Профили и топ пяти сохранены для всей матрицы Os/O2/O3.

Проверки: 8292 streams / 1763680 checks на сборку; GCC O0/Os/O2/O3, Clang O3,
ASan/UBSan, shared/install и C99. Ручной fuzz seed 1806: 336034 запуска / 21 с,
без находок. Генератор воспроизводим, исходники совпадают с измеренным snapshot.
Сборки и fuzz не пересекались с измерениями. Сравнение 1.8.0 остаётся историческим
в этапах 0/1, несинхронное отношение времен не выдаётся за новый speedup.

## Этап 3, дополнение — GNU time, размер кода, внешняя лаборатория

Выполнена свежая одинаковая PIC-сверка с исходной 1.8.0: Os/O2/O3,
GNU time real/user/sys, по три чередующихся повтора после прогрева,
100 млн кадров. Все четыре счётчика совпадают в 24 запусках.
Медианы real: Os 15.88 → 9.42 с; O2 13.03 → 6.59 с; O3 11.61 → 6.84 с.
Размер .text executable: референс 6833/18159/25304 байт, текущая v2
22129/32790/35174. У референса теперь те же PIC-условия; старые no-PIC
цифры не перезаписываются. [Полный отчёт](../../parser-v2-implementation/stage-3-antoull/reference-time/README.md).

Подготовлены `/home/meil/devel/linux/stomptalk-meta/run-claude-perf.sh` и
`claude-perf-lab/TASK.md`. Каждый внешний запуск получает новую копию work,
baseline, предыдущие варианты, 1.8.0, сырые evidence и отдельные experiments/reports.
Задача — независимое воспроизведение и небольшие измеряемые варианты ускорения
с обязательной оценкой простоты. JSONL, команды, статус, diff и неизменность
референсных входов сохраняются runner. Проверены подготовка и синтаксис;
сама модель Claude этим действием не запускалась. Production-код не менялся.

## Эксперимент — карты SIMD-разделителей

Изолированные варианты, production-код этапа 3 не менялся. Сохранены дерево
разбора, tailcalls, escaping и потоковое тело. Все варианты используют SSE2
по 16 байт: одна маска, карта 256 байт, карта до 32 КиБ, 128 offsets.

Purestomp 10 млн кадров, Δ медианного времени к текущему scanner:

| Flags | Одна маска | Карта 256 B | Карта 32 KiB | 128 offsets |
| --- | ---: | ---: | ---: | ---: |
| Os | +9.18% | +13.44% | +14.93% | +18.73% |
| O2 | +12.38% | +19.96% | +20.68% | +25.59% |
| O3 | +9.19% | +14.86% | +14.28% | +27.38% |

Длинная O3-проверка одной маски, 100 млн кадров: **6.899318 → 7.452725 с**,
**+8.02% времени**. На отдельных коротких O3-сценариях есть
локальный выигрыш; на 16 значениях по 1024 байта mask1 **+142%** времени.
Дополнительное состояние: 32 / 88 / 8216 / 536 байт. Общая скоростная
приёмка не пройдена: карты не переносим в основной parser. Это отрицательный
результат данной интеграции, не доказательство против любых двухэтапных parser.

Проверки: 15 CTest Release, 12 cursor-прогонов по 1 846 132 проверки,
4 ASan/UBSan-сборки + CTest/cursor, 875665 fuzz-запусков без находок.
Измерения последовательные, после завершения внешней лаборатории Claude.

## Внешнее ревью Claude — независимая проверка cold

Claude проверил noinline/cold для checked antoull. Root воспроизвёл cold
в отдельной копии и нашёл ошибки в причинном объяснении и сводке Os внешнего
отчёта. Сжатие кода реально; I-cache причина не доказана.

Purestomp 10 млн, SSE2: Os **+3.07%**, O2 **+3.66%**, O3 **−2.07% времени**.
Длинная O3-пара, 100 млн: **6.836723 → 6.702501 с**, **-1.96%**.
Scalar/SWAR-матрица и фрагменты также сохранены. .text O3 35174 → 30118 байт.
GCC Os/O2/O3 CTest и Clang ASan/UBSan CTest прошли; useful counters совпали.
Оценка простоты: один атрибут, но меняет вероятности путей и требует учёта
компилятора. Оценка ускорения: зависит от flags/backend, общего выигрыша нет.
Решение: не переносить cold в основной код; сохранить идею отдельного
исследования границы inline. [Ревью и собственные данные](../../claude-perf-review/README.md).

## Этап 4 — явный AVX2 scanner

32-байтный AVX2 scanner встроен в отдельное инстанцирование общего tailcall-дерева.
C API и размер состояния сохранены; выбирается backend 4, AUTO остаётся SSE2/scalar.
Широкие загрузки ограничены входом, хвост SSE2/scalar. Checks/guard pages,
GCC/Clang, ASan/UBSan, отключаемая сборка, shared/install/C99 прошли.
Fuzz с AVX2: 297374 запуска / 21 с, без находок.

GCC 15 O3, GNU time 100 млн: прежний AUTO **6.86 → новый 7.16 с**,
AVX2 **7.10 с**. Общего ускорения нет; регрессия baseline зафиксирована.
Full-parser с 16 значениями по 1024 байта: новый SSE2 **1026.09 → AVX2 617.84 нс**,
около −40%; byte input регрессирует. .text O3 **35174 → 42029** байт.
AVX2 остаётся opt-in для подходящей нагрузки; включение AUTO не обосновано.
[Подробности, 24 сценария и 12 профилей](../../stage-4-avx2/README.md).

## Матрица версий и PGO после этапа 4

Завершены четыре версии (1.2.2, 1.7.0, 1.8.0, v2), три оптимизации
и GCC 16.2.1 / Clang 23.1.4. Для v2 измерены SSE2/AVX2; все 30 сочетаний
профилированы, без lost samples. Полезные счётчики совпадают; CTest v2
прошёл во всех шести сборках. Отдельно сохранены ASCII и точный старый wire,
разброс, .text, perf top-5 и hardware counters. Накладные расходы API adapters
и разная поддержка escaping раскрыты в отчёте.

Исходный C-тест, 100 млн кадров, O3: 1.7.0 **14.61 / 12.56 с** GCC/Clang,
v2/SSE2 **6.66 / 5.16 с**. Исторические 8.351 с не воспроизвелись; контроль
без явного PIC не объясняет весь разрыв. [Матрица](../../version-matrix/README.md).

GCC 16/O3 PGO: SSE2 **6.74 → 6.08 с**, AVX2 **7.34 → 6.11 с** на 100 млн.
Есть регрессии длинных полей и escaped/AVX2. Profile-use unit suite прошёл
со штатным стеком; только generate-unit потребовал увеличения до 64 МиБ.
Оценка простоты: parser/API не меняются, добавляется двухэтапная сборка.
Оценка ускорения: полезно на части нагрузки, зависит от профиля; обычный Clang
в этом тесте быстрее. PGO не включён по умолчанию, следующий контроль — сервер.
[Обучение и результаты](../../pgo-study/README.md).
