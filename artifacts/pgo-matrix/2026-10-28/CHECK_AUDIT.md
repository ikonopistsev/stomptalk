# Проверки и ветвления: аудит текущей smid-2

Цель — сократить ненужную работу, сохранив простой parser. Подсчёт `if` в
исходнике не заменяет проверку машинного кода и времени полного разбора.
Ниже отделены внесённые изменения, доказанное дублирование и кандидаты.

## Внесено перед PGO-снимком

`src/stomptalk.cpp:103`, `src/names.cpp`: удалены `if (!view.data) return UNKNOWN`
из C-обёрток name classifiers. Их внутренние функции уже имеют
`assert(name.data || !name.size)`. Контракт `include/stomptalk/parser.h` теперь
явно требует доступный диапазон при ненулевой длине. `{nullptr, 0}` поддержан;
`{nullptr, 4}` не является неизвестным именем, это нарушение предусловия.
Три теста прежней обработки невалидных views удалены именно из-за принятого
пользователем контракта. Проверки неизвестных корректных имён и пустого view
сохранены. Публичный parser_execute по-прежнему возвращает ошибки аргументов.

Проверка указателя и switch по длине раньше проверяли разные свойства:
`nullptr/4` проходит ветку четырёхбайтных имён. Поэтому замена обоснована новым
предусловием, а не утверждением, что switch сам проверяет указатель. Parser
вызывает внутренний detect_method напрямую, а не C-обёртку; от этой правки
нельзя обещать ускорение горячего разбора.

В генераторе detect_method/detect_header и method_name/header_name общий
fallback перенесён после switch: `default:; ... return ...;`. Это стиль,
предложенный пользователем, без изменения результатов lookup. Ручная правка
method_name сохранена в генераторе, поэтому повторная генерация её не отменяет.

## На чём основан выбор 14/16 байт

`src/parser_states.hpp:99` и `:152` сначала отсекают уже найденный первый
content-length и длину имени, отличную от 14. Затем:

```cpp
curr > begin_ && p - curr == static_cast<ptrdiff_t>(key_.size)
    ? curr - 1 : nullptr
```

Для hdrline вместо p используется line.separator. Это найденное двоеточие,
оно строго внутри текущего входного диапазона. curr — начало текущего чистого
участка; key_.size — полная длина, включая ранее накопленное/декодированное.
Равенство длин доказывает, что весь ключ содержится в текущем участке.
`curr > begin_` разрешает читать предыдущий байт. Поскольку длина равна 14,
диапазон [curr-1, p+1) содержит ровно 16 доступных байт.

`src/is_header.hpp:33` выбирает wire!=nullptr → engine<B>::is_content_length_wire
(16 байт); иначе → portable memcmp(name, content_length_wire+1, 14).
SSE2/SWAR задаётся типом B, CPU не опрашивается для каждого заголовка.
AVX2 наследует 16-байтную проверку SSE2.

Да, происхождение token уже было известно раньше: token_owned_ проверяется в
append; finish_token затем сбрасывает его. Текущая реализация объединяет пути
и восстанавливает пригодность wire по диапазону. Это выбор реализации,
не требование SSE2. Кандидат: выполнить прямое сравнение в уже разделённых
ветках до finish_token, либо сохранить факт владения локально. Учесть целое
имя в начале нового input с LF в предыдущем: token_owned_ может быть false,
но чтение curr-1 всё равно недопустимо. Не добавлять постоянный флаг без нужды.
Сравнить получившийся код/регистры/ветви и whole-parser benchmark.

Размер 14 присутствует снаружи и внутри is_content_length. Внешний отсев
добавлен специально: GCC вычислял аргумент wire и для остальных длин.
При inlining повторное равенство обычно устраняется; проверять asm, а не
считать две записи выражения двумя исполняемыми проверками.

Для tailcall просмотрены все текущие состояния: после fail/reserve failure/
finish_value failure возвращают fail/stop_, OUTPUT_FULL возвращает сразу;
переход в следующий state идёт из успешной ветки. Это основание для
эксперимента с assert, но ещё не результат динамической проверки кандидата.

## Что похоже на повторение, но несёт контракт

- reserve: первая граница — невозможность вместить активный кадр, BYTE_LIMIT;
  вторая — занято результатами предыдущих кадров, OUTPUT_FULL. Разные решения
  и приоритет ошибок. Предыдущий A/B stackbuf/reserve уже не дал выигрыша.
- stackbuf::push: сохраняет reset-on-failure исходной реализации. Checked push
  и private push_reserved ранее сравнивались; обходной путь не принят по perf.
- Ограничения SIMD-загрузки в каждом 32/16/8 блоке нужны для хвоста. Выравнивание
  константы не разрешает читать за границами входного диапазона.
- assert в is_header, converter и name classifiers исчезает с NDEBUG; нельзя
  считать его runtime-затратой релизной сборки.
- sizeof...(Rest), selected.first и Size==0 в шаблонах известны при компиляции.
  Проверять остаточные инструкции, а не переносить ветки механически.
- Нулевой размер в runtime memcmp-обёртке обслуживает допустимый empty view.
  Удаление требует отдельного контракта о валидных указателях даже при size=0.
- Ошибки escaping, переполнение content-length, CRLF, терминатор, frame/header
  capacity и потоковый payload — свойства разбираемого потока/контракта,
  их нельзя заменить assert как ошибку программиста.

PGO измеряется на замороженном исходнике после изменений name helpers.
Остальные кандидаты намеренно оформлены для независимого ревью и отдельного A/B,
их эффект не примешан к оценке PGO.
