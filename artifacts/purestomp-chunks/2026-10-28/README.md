# purestomp: все размеры входного куска — 28.10.2026

Изменён только тест и его подключение в CTest. Исходники парсера и профиль PGO
совпадают с 52d1648. Корпус сохранён: 838 байт, 10 кадров, 35 заголовков,
67 байтов payload, один CONNECTED и один content-type:application/json.
Есть LF/CRLF, escaping, тело с content-length и без него, пустые тела.
SHA-256 корпуса: 57e696117dfd8d0f494528ebcf6b2f2dd1b3d1f75267daf057e0bfc005ee2d59.

## Запуск

```sh
# 100000 повторов по 10 кадров = 1 млн кадров на каждый из 838 размеров
./build/purestomp 3 100000 all > chunks.csv
# Один размер, например 3 байта
./build/purestomp 3 100000 3
# Целый буфер и прежняя итоговая строка счётчиков
./build/purestomp 3 100000
```

Каждый размер фиксирован на весь прогон; последний кусок может быть короче.
Размеры перебираются последовательно от 1 до 838, включая промежуточные
значения. Если execute оставил вход, сначала обрабатываются его результаты,
затем остаток того же куска. Между повторениями набора reset не вызывается.

## Корректность

Перед замером каждого размера выполняется отдельная сверка с разбором целого
буфера. Проверяются все методы, декодированные ключи/значения и их порядок,
наличие/значение content-length, BEGIN/COMPLETE, offsets и содержимое payload.
Вход копируется в переиспользуемый массив, затем затирается после обработки
результатов. Это выявляет сохранённые ссылки на старую входную память.
Проверка находится вне измеряемого интервала.

В замере парсер получает исходный постоянный корпус. Потребитель считает
вызовы execute, завершённые кадры, headers, JSON/CONNECTED и байты тела;
все итоговые счётчики сверяются для каждого размера. Время включает разбор
и обработку результата этим потребителем. Перенос/затирание входа из отдельной
проверки, выделение памяти, reset перед новым размером и печать не входят во время.

Прошли Debug/assert, Clang O3 PGO, GCC O3, ASan/UBSan. Короткий прогон всех
838 размеров проверен на scalar, SWAR, SSE2 и AVX2. CTest теперь содержит
stomptalk_c99_chunks (3 повтора набора на размер). Вывод — *-tests.log;
backend-checks.json фиксирует отдельные принудительные backend-ы.

## Измерение

Clang 23.1.4, O3, static PIC, SSE2, опубликованный профиль 52d1648,
P-core CPU 4 на i7-12700K. Один полный проход, 100000 повторов набора на размер.
Всего 838 млн завершённых кадров. Библиотечный PGO не переобучался под этот
замер: профиль и его происхождение сохранены в profile-used.json.

Это результаты одного прохода, без медианы повторов. Мелкие различия между
соседними размерами не доказывают выигрыш оптимизации. Число API-вызовов,
положение границ относительно кадров/полей и необходимое сохранение метаданных
меняются вместе с размером куска; этот тест не изолирует стоимость memmove.
Вызовы memmove здесь отдельно не подсчитываются.

Полные 838 строк — sweep.csv; команды, hashes бинарника/исходников/профиля
и итог проверки — run.json; GNU time всего запуска — sweep.time.
run.py воспроизводит измерение на данной машине после сборки указанного бинарника.
Пустой sweep.stderr означает отсутствие диагностик этого запуска.
