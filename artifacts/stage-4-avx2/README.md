# Этап 4 — выбираемый AVX2 scanner

Добавлен `src/backend/scan_avx2.hpp`: по 32 байта, exact movemask/ctz, проверка
доступной длины до загрузки, SSE2/scalar tail. Сканер встроен в AVX2-функции
состояний. Общая реализация tailcall-дерева — `src/parser_states.hpp`, baseline
и AVX2 инстанцируются отдельно. Target-атрибут относится только к состояниям
AVX2 и его scanner: общие helpers/dispatcher сохраняют базовую ISA. Нет
глобального -mavx2, нового состояния накопителя или дополнительной памяти.

C API backend 4 доступен при CPU/OS support и включённой сборке.
`STOMPTALK_BUILD_AVX2_PARSER=OFF` исключает его независимо от names backend.
AUTO остаётся SSE2/scalar. Для 14-байтного content-length используется прежняя
подготовленная 128-битная константа; AVX2 не означает 256-битную загрузку короткой
строки. Body с длиной пропускается арифметически, без чтения; без длины — memchr.

## Проверки

GCC Os/O2/O3 + debug, Clang O3, Clang ASan/UBSan, отключение AVX2 parser,
отдельное отключение AVX2 names, shared/install, внешний C99-клиент с backend 4.
Все CTest прошли. Дифференциальный fuzz теперь включает AVX2: 297374 запуска за
21 секунду, без находок. Прямой scanner-тест проверяет все значения байта,
первые события, границы вектора, хвосты и защищённые страницы с обеих сторон.
Общая protocol-suite и её нарезка input запускаются для backend 4 тоже.

Проверен машинный код Os/O2/O3: AVX2 сравнения и movemask внутри состояний;
вызовов scan_header/header_scanner нет. Есть хвостовые indirect jumps.
В baseline parser.cpp/stomptalk.cpp AVX-инструкций нет. Проверка реального CPU
без AVX2 через эмулятор не проводилась; проверена сборка с backend OFF.

## Замеры GCC 15.3.0 на i7-12700K

Одинаковые CMake static PIC, CPU 2, powersave, без LTO/-march=native. Сначала
все сборки, тесты и fuzz, затем последовательные замеры. Исходники каждого
варианта зафиксированы и хэшированы. Перед этапом — v2 после antoull.

Purestomp, 10 млн кадров, медианы пяти повторов после прогрева, секунды:

| Flags | До, SSE2 | После, SSE2 | После, AVX2 |
| --- | ---: | ---: | ---: |
| Os | 0.9324 | 0.9862 | 0.9634 |
| O2 | 0.6502 | 0.6710 | 0.6809 |
| O3 | 0.6829 | 0.7181 | 0.7056 |

**Общего ускорения короткого purestomp нет.** Добавление AVX2-инстанцирования
сопровождается просадкой baseline SSE2; причина через I-cache не установлена.
Порядок определений baseline helpers/states был восстановлен перед финальным
запуском, но это просадку не устранило. Предварительный запуск сохранён отдельно,
прерванные данные не смешаны с финальными.

GNU time, O3, 100 млн кадров, три повтора после прогрева: прежний AUTO **6.86 с**,
новый AUTO **7.16 с**, новый AVX2 **7.10 с**. Это сохраняется как регрессия этапа,
а не объявляется ускорением за счёт ISA.

Full-parser длинные поля выигрывают. O3, 16 значений по 1024 байта:
SSE2 нового варианта **1026.09 → AVX2 617.84 нс/кадр** (около −40%).
При значениях по 128 байт: **315.84 → 271.17 нс** (−14%). Byte-input, напротив,
**1471.13 → 1639.19 нс**. Поэтому AVX2 оставлен явным выбором для измеряемой
нагрузки, AUTO на него не переключён. Это не готовая универсальная оптимизация.

.text executable: Os **22129 → 25726**, O2 **32790 → 37749**, O3 **35174 → 42029**
байт. В executable теперь четыре parser backend; размер .text не равен размеру
горячего пути одного backend и не доказывает cache misses.
